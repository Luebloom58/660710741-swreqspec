# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

## 1. สรุปแนวทาง

1. ผู้รับบริการที่ผ่านการยืนยันตัวตนจะเลือกแพ็กเกจ วัน และช่วงเวลาตรวจภายใน 30 วัน (FR-BKG-01, IF-IDP-01)
2. ระบบจะแสดงช่วงเวลาที่ไม่ว่างเป็นสีเทาและป้องกันการเลือก พร้อมจำนวนที่นั่งของช่วงเวลาที่ว่าง (FR-BKG-01)
3. การยืนยันการจองจะตรวจคิวซ้ำและทำการจอง ตัดที่นั่ง และออกหมายเลขคิวเป็นชุดเดียวกัน (FR-BKG-02, FR-BKG-04, ASM-03, ASM-04)
4. การส่งข้อความจะทำแบบ asynchronous ผ่านช่องทางที่ลงทะเบียนไว้ และมีคิวส่งซ้ำตามข้อกำหนด (FR-BKG-05, IF-NOT-01, NFR-REL-02, ASM-05)
5. กรณีระบบภายนอกล้มเหลวจะหยุดการจองและแจ้งให้ลองใหม่ ส่วนรายละเอียดที่อยู่ใน Open Questions จะยังไม่สร้าง (IF-IDP-01, IF-HIS-01, Q-01, Q-02, Q-03)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| MySQL | CON-TECH-01 | ฐานข้อมูลหลักของการจอง โควตา และคิวส่งข้อความ |
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | หน้าจอเลือกแพ็กเกจ วัน และช่วงเวลา |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | API สำหรับการค้นหา ตรวจสอบ และยืนยันการจอง |
| TLS 1.2 ขึ้นไป | NFR-SEC-01 | บังคับใช้กับการรับส่งข้อมูลการจอง |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Patient` | `hn`, ช่องทางแจ้งเตือนที่ลงทะเบียนไว้ | IF-HIS-01, IF-NOT-01, FR-BKG-05 |
| `Package` | `package_id`, `name`, ข้อมูลเงื่อนไขการใช้ช่วงเวลา | FR-BKG-06 |
| `TimeSlot` | `slot_id`, `date`, `start_time`, `end_time`, `capacity`, `remaining_seats` | FR-BKG-01, FR-BKG-03, FR-BKG-04, ASM-01, ASM-02 |
| `Booking` | `booking_id`, `hn`, `package_id`, `slot_id`, `queue_number`, `status`, `created_at` | FR-BKG-02, FR-BKG-04, FR-BKG-05, ASM-04 |
| `NotificationJob` | `job_id`, `booking_id`, ช่องทาง, `attempt_count`, `next_attempt_at`, `status` | FR-BKG-05, NFR-REL-02, IF-NOT-01, ASM-05 |
| `AuditLog` | `actor_id`, `accessed_at`, `hn`, รายละเอียดการเข้าถึง | DOM-PDPA-01, AC-BKG-06 |

`Booking` ต้องไม่มีฟิลด์เลขบัตรประชาชน โดยใช้ `hn` ที่ได้จาก HIS เป็นตัวอ้างอิงภายในระบบ (IF-HIS-01)  
การสร้าง `Booking`, การลด `remaining_seats` และการออก `queue_number` ต้องอยู่ในธุรกรรมเดียวกัน (FR-BKG-04, ASM-03, ASM-04)

## 4. API / หน้าจอ

| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| `GET /booking/slots` | รับแพ็กเกจและช่วงวันที่; คืนวัน ช่วงเวลา สถานะว่าง/ไม่ว่าง และจำนวนที่นั่ง | FR-BKG-01, FR-BKG-06 |
| `POST /booking/validate` | รับวันและ HN; คืนผลว่ามีคิวที่ยืนยันแล้วแต่ยังไม่เข้ารับบริการหรือไม่ และหมายเลขคิวเดิม | FR-BKG-02, ASM-02 |
| `POST /booking` | รับแพ็กเกจและช่วงเวลา; คืน `booking_id`, หมายเลขคิว และสถานะการส่งคำขอแจ้งเตือน | FR-BKG-03, FR-BKG-04, FR-BKG-05, ASM-03, ASM-04 |
| `GET /booking/{booking_id}` | รับรหัสการจอง; คืนรายละเอียดการจองและหมายเลขคิวโดยไม่เปิดเผยเลขบัตรประชาชน | FR-BKG-04, IF-HIS-01 |
| `POST /integrations/idp/verify` | รับผลจาก IDP; คืนผลยืนยันตัวตนหรือข้อผิดพลาดให้ลองใหม่ | IF-IDP-01 |
| `GET /integrations/his/patient` | รับข้อมูลค้นหาตาม IF-HIS-01; คืน HN หรือข้อผิดพลาดให้ลองใหม่ | IF-HIS-01 |
| `POST /integrations/notification-jobs` | รับงานแจ้งเตือน; คืนสถานะงานแบบ asynchronous | IF-NOT-01, FR-BKG-05, NFR-REL-02 |
| หน้าจอเลือกแพ็กเกจและเวลา | แสดงแพ็กเกจ วัน ช่วงเวลาที่ว่าง/ไม่ว่าง และจำนวนที่นั่ง | FR-BKG-01, FR-BKG-06 |
| หน้าจอผลการจอง | แสดงหมายเลขคิว ผลการจอง และข้อความแจ้งเตือนเมื่อส่งข้อความไม่สำเร็จ | FR-BKG-02, FR-BKG-03, FR-BKG-04, FR-BKG-05 |

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-TECH-01 | ใช้ MySQL ในหัวข้อเทคโนโลยีและโมเดลข้อมูล | ใช้แล้ว |
| DOM-PDPA-01 | Entity `AuditLog` และการบันทึกทุกการเข้าถึงข้อมูลผู้รับบริการ | ใช้แล้ว |
| IF-IDP-01 | ขั้นตรวจสิทธิ์ก่อน API ข้อมูลผู้รับบริการ และกรณีล้มเหลวให้ลองใหม่ | ใช้แล้ว |
| IF-HIS-01 | Adapter/API HIS, การใช้ `hn` และการไม่เก็บเลขบัตรประชาชน | ใช้แล้ว |
| IF-NOT-01 | `NotificationJob` และการส่ง asynchronous ผ่านช่องทางที่ลงทะเบียน | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-BKG-01 | `test_AC_BKG_01_successful_booking` | เตรียมช่วง 09.00 น. เหลือ 1 ที่ ยืนยันการจอง ตรวจว่าบันทึกสำเร็จ มีหมายเลขคิว และเหลือ 0 ที่ |
| AC-BKG-02 | `test_AC_BKG_02_reject_duplicate_same_day_booking` | เตรียมคิวที่ยืนยันแล้วแต่ยังไม่เข้ารับบริการในวันเดียวกัน จากนั้นจองซ้ำ ตรวจว่าถูกปฏิเสธและคืนหมายเลขคิวเดิม |
| AC-BKG-03 | `test_AC_BKG_03_full_slot_without_duplicate_booking` | จองที่นั่งสุดท้ายให้ผู้ใช้หนึ่งราย แล้วให้ผู้ใช้อีกรายยืนยัน ตรวจข้อความเต็ม ตัวเลือกใกล้เคียงไม่เกิน 3 รายการ และไม่มีรายการซ้อน |
| AC-BKG-04 | `test_AC_BKG_04_notification_retry_keeps_booking` | จำลองระบบแจ้งเตือนไม่ตอบสนอง ตรวจว่าการจองและหมายเลขคิวยังอยู่ และงานถูกส่งซ้ำ 3 ครั้งภายใน 10 นาทีแล้วหยุด |
| AC-BKG-05 | `test_AC_BKG_05_slot_search_p95_200_users` | จำลองผู้ใช้พร้อมกัน 200 คน วัดเวลาตอบสนองการค้นหาช่วงเวลา และตรวจ p95 ไม่เกิน 2 วินาที |
| AC-BKG-06 | `test_AC_BKG_06_audit_log_on_booking_access` | เปิดดูข้อมูลการจอง ตรวจ `AuditLog` ว่ามีผู้เข้าถึง เวลา และ HN |

NFR-SEC-01 และ NFR-USE-01 ยังไม่มี AC เฉพาะใน spec จึงต้องตรวจเป็น non-functional test แยกต่างหากเมื่อทีมกำหนดเกณฑ์เพิ่มเติม (Q-03)

## 7. ลำดับงาน

1. กำหนด schema ของ `Patient`, `Package`, `TimeSlot`, `Booking`, `NotificationJob` และ `AuditLog` โดยไม่เก็บเลขบัตรประชาชน (CON-TECH-01, IF-HIS-01, DOM-PDPA-01)
2. สร้าง integration boundary สำหรับ IDP และ HIS พร้อมการหยุดการจองเมื่อระบบภายนอกล้มเหลว (IF-IDP-01, IF-HIS-01)
3. สร้าง API และหน้าจอค้นหาช่วงเวลาภายใน 30 วัน พร้อมสถานะสีเทาสำหรับช่วงที่ไม่ว่าง (FR-BKG-01, FR-BKG-06)
4. สร้างการตรวจคิวซ้ำตามวันและเขตเวลา Asia/Bangkok (FR-BKG-02, ASM-02)
5. สร้างธุรกรรมยืนยันการจองที่รองรับการแข่งขันที่นั่งสุดท้ายและหมายเลขคิวรายวัน (FR-BKG-03, FR-BKG-04, ASM-03, ASM-04)
6. สร้าง `NotificationJob` แบบ asynchronous และกลไกส่งซ้ำไม่เกิน 3 ครั้งภายใน 10 นาที (FR-BKG-05, NFR-REL-02, IF-NOT-01, ASM-05)
7. เพิ่มการบันทึก audit log และตรวจการรับส่งข้อมูลด้วย TLS 1.2 ขึ้นไป (DOM-PDPA-01, NFR-SEC-01)
8. สร้าง automated tests ตาม AC-BKG-01 ถึง AC-BKG-06 และทดสอบประสิทธิภาพ/การใช้งานตามเกณฑ์ที่มี (AC-BKG-01 ถึง AC-BKG-06, NFR-PERF-01, NFR-USE-01)

## 8. สิ่งที่ยังไม่ทำ

- **Q-01:** หาก HIS ไม่พบผู้รับบริการหรือพบข้อมูลมากกว่าหนึ่งรายการ ต้องแสดงผลและดำเนินการอย่างไร? -> ถามเจ้าหน้าที่เวชระเบียน  
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-02:** “ยืนยันภายใน 3 นาที” ใน Goal เริ่มนับและสิ้นสุด ณ ขั้นตอนใด? -> ถามทีมเจ้าของกระบวนการ  
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-03:** ต้องมี Acceptance Criteria สำหรับ FR-BKG-06 และ NFR-SEC-01 เพิ่มเติมหรือไม่? -> ถามทีมผู้ตรวจข้อกำหนด  
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
